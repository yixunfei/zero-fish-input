# v0.7.6 validation

Date 2026-11-18. The public artifact is a Debug-signed testing prerelease,
application ID `dev.zeroinput.ime.debug`, version `0.7.6-debug`, version code 13.
It supports Android API 26 and later and contains arm64-v8a, armeabi-v7a and
x86_64. Production Release splits remain unsigned.

## Review and repairs

Reviewed the pending November 18 audit repairs, their callers, failure paths,
tests and distribution boundaries, preserving the original working-tree patch.
The earlier audit and its repair verification are in
[the audit directory](../audits/). Two additional defects were repaired:

- Re-reading equal AI configuration replaced the redacted snapshot object, so
  exact-identity credential resolution could reject a queued request even though
  settings had not changed. Equal reloads now retain the submitted snapshot;
  revocation, explicit saves and changed metadata still invalidate old work.
- A failed settings save enabled editing of an empty error configuration,
  allowing a subsequent operation to overwrite persisted providers. Ordinary
  reloads also could not recover editing after revocation. Failed saves now drop
  drafts and disable editing until durable providers are reloaded. Only settings
  may recover editing with both activation switches forced off; that recovery
  never publishes transport authorization and rejects stale revisions.

The snapshot regression failed before the fix. A real bounded storage-queue
rejection reproduced the settings recovery failure on the emulator before the
fix; the resulting regression passes with saved credentials preserved and
transport still revoked. Negative tests cover stale recovery and explicit-save
revocation. Platform expectations now verify draft clearing on stop and
credential-free application snapshots. Encrypted formats, key aliases, approved
network paths and permissions are unchanged.

This was a review of the affected paths and their integration, not an exhaustive
proof of every project path. No further confirmed defect remained in that scope.

```powershell
./gradlew.bat test privacyCheck :app:lintDebug :app:lintRelease `
  :app:assembleRelease :app:assembleDebugAndroidTest `
  -PrequireRime=true --no-parallel --max-workers=4
python -m unittest discover -s tools/resources -p 'test_*.py'
python -m unittest discover -s tools/dictionaries -p 'test_*.py'
./tools/test-test-apk-artifact.ps1
./tools/test-instrumentation-result.ps1
./tools/test-jni-failures.ps1 -SdkRoot D:/env/AndroidSDK -Serial emulator-5580
./tools/package-test-apk.ps1 -Abi universal -MaxApkBytes 180000000 -SkipChecks `
  -OutputDirectory app/build/outputs/test-apk-v0.7.6
```

`-SkipChecks` reused the immediately preceding complete test/privacy/Lint run;
it did not omit APK content, ABI, signature or permission validation. Gradle
reports contain 87 pure JVM passes plus 1,000 passes and two opt-in live-provider
skips in each Android Debug/Release variant: 2,087 passes, four skips and zero
failures/errors across variants. There are 1,089 distinct JVM cases, of which
1,087 passed and two opt-in cases were skipped. Reused Gradle results and variant
repetitions are not new distinct cases. Both Lint reports say `No issues found`.
Source and Debug/Release merged-manifest privacy checks passed.

Resource tooling passed 16 tests and dictionary tooling passed 18. Packaging
locator/reset checks passed. The instrumentation-output checker passed two valid
and 18 invalid cases. Native failure injection passed using the production JNI
helpers on isolated Android x86_64. All three Debug and Release native ABIs built
with real Rime required. Each Release APK passed full dictionary/model/native
verification, ELF architecture checks and exact comparison of all 31 bundled
license/notice files. Release manifests disable backup and debugging. The
separate notices archive contains the same 31 files.
