# v0.3.0 release validation

Date: 2026-09-23. Public artifact: Debug-signed testing prerelease.

## Environment and scope

- Windows/PowerShell, repository Gradle 8.14 wrapper, Android SDK 36 and NDK 28.2.
- Fixed librime 1.13.1 sources and existing pinned language/model assets.
- FlutterTest x86_64 emulator, Android 17/API 37; no physical ARM device.
- Version 0.3.0-debug, versionCode 3, application ID dev.zeroinput.ime.debug.
- No new dependency, permission, persistent format or production signing key.

## Build and artifact checks

`./tools/package-test-apk.ps1` ran full unit tests, privacyCheck, app Debug Lint,
and the three-ABI universal native build with `-PrequireRime=true`, without skipped
checks. The JVM/Android unit variants executed 464 tests with zero failures,
errors or skips. APK signature, package, ABI and permission checks passed.

`./gradlew.bat :app:assembleRelease -PrequireRime=true --no-parallel` also passed,
including R8/resource shrinking and vital Lint. Each of the three unsigned ABI
APKs contains its native Rime library and the same 17 license/source assets.

The APK includes all three librime libraries and 17 nonempty license/source
assets. Its SOURCES.md points to the v0.3.0 source tag. The separate notices
archive and checksum list accompany the APK.

The v0.2.0 comparison APK has SHA-256

## Device regression preparation

The initial full run exposed test harness defects rather than being accepted as
a passing release run. Related-reading tests occupied the serial worker needed
by their newly lazy session, the association fixture used a fixed delay instead
of waiting for engine handoff, and a clipboard fixture assumed the selected
keyboard. Tests now release the worker, wait for actual readiness and explicitly
select/restore their required IME. Their nine targeted regressions passed.

A subsequent full run exposed process-wide fault-test contamination: the missing
dictionary test closed the normal Rime runtime without restoring it. Cleanup now
restores and verifies the application runtime before later editor tests execute.
Existing assertions and product code were not relaxed to accommodate failures.
These corrections affect only the test APK; the public universal APK is unchanged.

## Final device results

The exact universal APK above was installed with `adb install -r` and tested with
the rebuilt instrumentation APK. The final full invocation reported
`OK (173 tests)` in 218.839 seconds, with zero failures. Eight cases returned
assumption skips: six required ZeroInput to be the default IME, and two require
an explicitly configured disposable-device test PIN. The runner's summary does
not count assumption failures as ignored; TestRunner events were checked too.

After explicitly selecting ZeroInput, all eight SystemClipboardPlatformTest
cases passed in 23.381 seconds, with no assumption skips, covering the six
previously skipped clipboard cases. Across these final runs, 171 distinct
device cases passed; the two PIN-dependent authentication flows remain unrun.
No device lock credential was configured or changed for this release.

The suite covers native pinyin/options/nine-key, candidate paging, input latency,
preparation UI, privacy, association chains, encryption/storage failure cases,
rotation/themes/layout, private clipboard state and platform clipboard controls.
The three-ABI public APK hash was rechecked after the test runs and is unchanged.

Logs are local build artifacts: `build/release-030-package.log`,
`build/release-030-release-build.log`, `build/release-030-device-targeted.log`,
`build/release-030-fixture-build.log`, `build/release-030-universal-final.log`
and `build/release-030-clipboard-platform.log`. Initial failing runs are preserved

## Remaining boundaries

Physical ARM devices, vendor editors, broad Android 8+ coverage, real biometric
and credential flows, battery and long-running pressure tests remain unverified
for this release. No production signing key was generated; unsigned Release
outputs are not public installable artifacts. No claim is made that initial Rime
deployment is faster, phrase quality is solved, or the default-off experimental
model meets its previously missed accuracy gate. Fixed public association
fixtures are development tests, not population-level quality measurements.

Historical fix evidence is recorded in the Chinese input availability, security
storage, word association and clipboard validation documents. Those historical
device results must not be interpreted as fresh physical-device testing here.
