# v0.2.0 release validation

Date: 2026-09-09. Scope: the v0.2.0 source tree, including the input improvements,
default-off Mini ranking experiment and Android 16 clipboard fixture repairs.
Earlier v0.1.0 and model evaluation reports remain historical evidence.

## Build and automated checks

Environment: Windows/PowerShell, JDK 17, Gradle 8.14, Android SDK 36,
NDK 28.2.13676358 and the pinned librime 1.13.1 sources. From the repository root:

```powershell
./tools/package-test-apk.ps1
./gradlew.bat :app:assembleRelease :app:assembleDebugAndroidTest -PrequireRime=true --no-parallel
```

- The packaging script ran root `test`, `privacyCheck` and `:app:lintDebug`, then
  built all three Debug ABI packages and the universal APK with real Rime.
- Root `test` passed: 334 executions across Debug, Release and pure-JVM modules,
  zero failures, errors or skips. This includes 171 Debug/JVM cases; unchanged
  Gradle tasks reused up-to-date results.
- `privacyCheck`, Debug/Release merged-manifest checks, Debug Lint and Release
  vital Lint passed. Existing permission and backup boundaries remain enforced.
- All three unsigned Release ABI packages and the instrumentation APK built.
  Release APKs are nondebuggable; no production signing key was generated.
- All seven main APKs contain the exact pinned Mini graph and vocabulary hashes,
  Rime and ONNX native libraries for the intended ABIs, and current license/source
  notices. The universal package contains no unsupported x86 libraries.
- The public Debug package has no `testOnly` flag and installs with plain
  `adb install -r`. The separate external clipboard source exists only in the
  instrumentation APK; Debug editor fixtures are absent from Release.
- APK signatures, notice archive bytes and SHA-256 manifests passed inspection.
  Source hygiene checks found no generated model/runtime binaries, build caches
  or credential patterns in the files selected for Git.

## Device verification

The new universal APK and matching instrumentation APK were installed on
`ZeroInputModelApi36` (Android 16/API 36, x86_64). ZeroInput was explicitly selected
as the default IME to exercise all clipboard platform tests. Commands:

```powershell
adb -s emulator-5554 install -r app/build/outputs/test-apk/20260909-003934/zero-finish-input-0.2.0-debug-universal.apk
adb -s emulator-5554 install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5554 shell ime enable dev.zeroinput.ime.debug/dev.zeroinput.ime.ZeroInputService
adb -s emulator-5554 shell ime set dev.zeroinput.ime.debug/dev.zeroinput.ime.ZeroInputService
adb -s emulator-5554 shell am instrument -w -r dev.zeroinput.ime.debug.test/androidx.test.runner.AndroidJUnitRunner
```

All 131 instrumentation tests passed in 184.003 seconds, with zero failures or
skips. This includes actual Rime/model routing, the privacy matrix, candidate
editing, keyboard layouts and all clipboard platform cases. Installed main/test
APK hashes match the local artifacts. The original system IME was restored after
the run and the emulator started for validation was shut down.

## Remaining validation limits

ARM hardware execution, vendor editor behavior, physical biometric/credential
flows, battery use and long-duration memory pressure were not measured in this
release run because no physical test device was available. All three ABIs were
built and inspected; device execution was limited to the API 36 x86_64 emulator.

The prior model quality/performance results were not rerun: the model, threshold
and runtime are unchanged. The original quality regression gate remains failed,
and the explicitly accepted experiment remains off by default. See
[model integration validation](https://github.com/yixunfei/zero-fish-input/blob/379a463d8e5e2207815cd289c5c532d7211b99c2/docs/model-integration-validation.md) for numerical
results, failure boundaries and the repeated clipboard regression checks.
