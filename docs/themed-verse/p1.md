## 运行 P1

从仓库根目录运行，需 Python 3.11+、两套锁定 Rust 帮助程序及已准备的 16 张公开词表。Cargo 依赖已缓存时可加 `--offline`。资源编译及收发均离线。

```powershell
cargo build --locked --manifest-path tools/stego-vectors/Cargo.toml
cargo build --locked --release --manifest-path tools/themed-verse/rmw-probe/Cargo.toml --target-dir .tmp-evidence/rmw-target
$trial = Join-Path '.tmp-evidence' ("themed-verse-p1-" + [guid]::NewGuid())
$profile = Join-Path $trial profile
python -B tools/themed-verse/build_p1_profile.py "$profile"
python -B tools/themed-verse/check_joint_codec.py "$profile" --report "$trial/results.json"
```

调用方式为 `python -B tools/themed-verse/joint_codec.py --profile "$profile" seal fixture.key original.txt verse.txt`，收端用 `open fixture.key verse.txt recovered.txt`。密钥文件含 32 个公开夹具字节。成品和正文按原始字节读写，输出使用新路径。发端加 `--require-20` 时，未过线返回 `below-20`。其余有区别的结果包括 `missing-resource`、`profile-mismatch`、`frame-capacity`、`carrier-capacity` 和 `carrier-rejected`。

验收将接收程序和帮助程序放进一个独立目录，接收资源只含 `profile.json`、句池、词频、位置反查表及三份预置字典。接收进程从该目录启动，输入只有配置、公开夹具密钥和完整成品。目录里没有原始文档、训练材料、正向索引、候选清单、明文长度或模式标记。通过全部验证后才发布结果文件，失败时保留既有文件。

## 公开配置和研究模式草案

| 集句句池 | 固定天空、水、山林三类原池及其去重并集，组内按码点升序。以并集开始，前句最右的意象字决定进入下一类。版式为五字一句、逗号和句号相间、末句句号，每四句间加 LF |

按锁文件的表序，逐表跳过首个单独的 `...`，随后制表符分列。两列及以上的每行占一个编号，重复词面和多音行都计数。权重取可解析的数字第三列，其余为零。短码先取 `zi` 中每个单字的最高权重，按权重和词面降序取前 4,096 个并指向各单字首次出现的行。再取 `jichu` 按权重、词面、行号降序的前 4,096 行。发端优先用同词面最低短码，无短码时用首次出现的长码。位置流 `00–7f` 直写 ASCII，`80–bf` 加两字节为 `0x800000 + 行号`，`c0–df` 加一字节为 `0xc000 + 短码序号`，`ff` 加一字节长度减一和 1–64 B 字面量。编码在字符边界按总字节数择短，平局按当前消耗字符数和码字升序。收端限制位置解压至原长的 3 倍，拒绝未知索引、按键事件标记、截断和与原长不符的流。

一次候选生成比较下列顺序。研究编号同时决定同档优先级。解压只接受完整 zlib 流，使用每种模式固定的字典字节和输出上限。普通或带字典 zlib 的压缩位流以参考版本生成，收端按流格式解压。RMW 仅在逐字节保真时入选。

| 模式 | 研究编号（十进制） |
|---|---:|
| 原始 UTF-8 `raw` | 0 |
| 普通 zlib `zlib` | 1 |
| 自定义变长码 `words` | 2 |
| UTF-8 字典 zlib `dict-utf8` | 3 |
| GB18030 字典 zlib `dict-gb` | 4 |
| RMW `rmw` | 5 |
| 静态位置 `position` | 16 |
| 位置 + zlib `position-zlib` | 17 |
| 位置 + 固定字典 zlib `position-dict` | 18 |

试解并逐字节比较后，保留长度 1–2,045 B 的候选。3 B 描述符为模式 u8、原长大端 u16，接着放编码流。单层 AES-256-GCM 主机帮助程序以 `ZeroInput/host-verse/v1/` 加小写配置摘要作为实验 cover。封装大小 `E = 98 + 64 * ceil((36 + 3 + 流长)/64)` 已计入头、元数据、随机数、标签和填充。先取最小 E，再按模式编号择优。以系统随机数加密一次，混合进制将密文作为大端整数从最低位逐句输出。首个使累积候选乘积达到 `256^E` 的句子收尾；收端从最后一跳恢复唯一的 E，并回渲染比对成品。两层认证成功后才解码正文。详细失效条件和正式编号、域分离及完整表面绑定的评审保留在 P3。[首发评审项](implementation-plan.md#3-数据流边界与失败处理)

[短公开向量](p1-vectors.json)的 `word-sample` 为 27 B 的 `input Rime and editor data\n`。描述符 `02 00 1b` 选变长码，随后 17 B 为 `3ab98db982fdee5d7a8b53e772f60b583c`。起始位 `0011101010 11100 11000110110` 依次恢复 `input`、空格、`Rime`。解出 27 B 时恰好耗尽位流。20 B 帧正文加 36 B 固定字段，填充到 64 B，实际封装 162 B，固定成品 1,770 B。另两条固定向量使用实际入选位置字典的 v0.7.5 和含 `𠀀`、CRLF、emoji、组合字符、NUL 的字节输入。向量保留可见成品、压缩流、封装长度及恢复摘要，随机回归比较入选模式、封装档和恢复结果。

## P2 输入与评审

下一阶段按体裁准备至少各 50 篇 1,024–2,048 B 的独立公开工作记录和自由叙事。提前冻结许可、来源、按作者分离的训练／校准／留出清单、去重口径和容量／自然度联合作为指标的阈值。逐体裁报告可恢复比例、每种新增过线数、失败原因、行数与两种长度的 P50/P95、重复率。匹配普通集句和人作，对整篇做至少三人盲评。还需测量 Android 索引的包体、冷加载和峰值内存。当前交付的验收范围是 Python/Rust 主机。正式消息格式、安全绑定、独立 Kotlin 互通及产品入口分别按后续阶段评审。[分阶段规划](implementation-plan.md#5-阶段依赖与完成条件)
