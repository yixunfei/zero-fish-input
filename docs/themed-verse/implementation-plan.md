## 1. 交付目标与已有证据

用户主动输入秘密正文并选择生成一篇有明确主题的集句。发端取原始 UTF-8 字节，比较多种无损表示，只加密选中的一份。收端凭完整可见文本、约定的公开配置和原凭据，逐字节恢复原文。另行生成公开文字的场景与既有“对公开草稿保留原意”的研究分别验收。

逐条以 `S` 表示原始秘密正文 UTF-8 字节数，`V` 表示最终全文 UTF-8 字节数。**20% 验收用整数判断 `V <= 5*S`**。标题、标点、换行和任何随文传递的配置提示均计入 V。每条还须符合 8,192 UTF-16 单元、16,384 UTF-8 字节的整条载体上限。另报是否能放入 512 单元且 1,536 B 的普通公开草稿。原文最长 2,048 B，首批质量评测聚焦 1,024–2,048 B 中文长文。

| 已有交付 | 可复核的结果 | 对正式实现的含义 |
|---|---|---|
| 自定义词／字前缀码、字面量转义、按封装档位择优、实际单层 AES 收发 | 9 篇实际项目文档全部恢复，2/9 过 20%；v0.7.5 的 1,108 B 正文可用自定义流表示为 408 B | 保留字节保真与合法回退；比较最终档位，并记录每种候选的增量贡献 |
| 静态词库位置、位置流的二次压缩、独立反查 | 同批 9 篇全部恢复，6 篇各少 64 B，过线增至 4/9。v0.7.5 的位置流为 676 B，经固定字典压缩到 291 B，最终 5,255 B，利用率 21.08% | 将静态位置加入同一选择器。给解码器提供可按编号反查的完整公开资源 |
| 原生全拼／简拼和候选序号重放 | 9 篇中按键方案均未超过原基线，与位置混用也没有额外缩短；两篇普通设计文采用位置后仍低于 20% | 原生重放保留为实验对照。正式解码只依赖版本化数据，不调用实时输入会话 |

所有过线样本均为发布说明；合成巡检表单单列。历史实现是 Python／Rust 主机研究和隔离模拟器上的原生按键对照。跨实现互通、独立长文盲评、移动端资源和性能尚待验证。[实验数据与命令](prototype.md) · [研究设计](../natural-wording-steganography.md)

## 2. 两种优化怎样组合

**首选实现是同一封装内逐条择优。** 自定义词／字码直接利用原文的符号频率；位置码先把命中的词、短语、完整句段换成稳定编号，再利用编号序列中的重复结构。两路都保留原始字节转义。同一条消息只记录一个可明确解码的模式。实现顺序如下。

1. 严格取得 UTF-8，不归一化、不去空白、不替换无效输入。对每个候选生成有界字节流，用对应收端规则试解并比较全部字节。候选不保真、过大或资源无效时剔除该项。原样候选也须满足帧内限额。
2. 候选清单至少有原始 UTF-8、自定义词／字码、静态位置流、位置流＋zlib、位置流＋固定公开字典 zlib。保留普通 zlib 和既有领域字典方案作消融对照。RMW 保留作主机基线，是否随包取决于留出集上的独有收益、Unicode 保真、许可与包体审核。先用公开历史语料经**同一位置编码器**变换后训练位置流预置字典，冻结字典原始字节和哈希。
3. 固定选择顺序。按用户已选凭据、算法及层数计算完整封装大小，先取最小封装档，同档沿用已冻结的较简单模式优先级。头、描述符、随机数、标签、帧填充及载体终止成本均进入预算。比较自定义单路、位置单路和联合选择三组，使“某模式被选中”和“它新增了过线样本”可分别复核。
4. 如考虑在同一位流内混用词库行号和自定义前缀码，另做消融实验：给行号分配明确定义的前缀，计入模式位、行号及补位，做最短解析，再与逐条择优比较。只有独立留出集出现净降档、可互解且成本可接受时才提议新模式编号。这种混编的收益目前没有实测结论。

## 3. 数据流、边界与失败处理

**发端。** 在独立隐写草稿取一次正文快照 → 后台固定资源代次 → 构建候选并逐字节试解 → 选择封装档并做长度预检 → 以系统安全随机数加密一次 → 用约定主题和已生成上文确定每个位置的候选 → 渲染规范全文 → 复查两种长度、20% 和完整收发自检 → 在有效工作区展示预览。严格模式不达标时返回容量不足，不因接近门槛而重试随机数。研究工具可以导出低于门槛的公开样本，必须计入分母。

**收端。** 用户显式选择隐写解密和公开配置 → 先限制输入长度、校验严格 Unicode 与完整规范版式 → 按已恢复上文重建候选和密文 → 校验头部、模式及昂贵 KDF 的确认条件 → 验证元数据和所有层的认证 → 校验编码编号、原长及输入界限 → 有界解压、反查词面并核对原长和严格 UTF-8 → 在当前操作代次有效时发布结果。失败不显示部分正文。按协议将恢复的密文重新映射成规范全文，与输入逐字节比较，覆盖末行、填充、标点与换行。

**协议评审要解决的三个差距。**

- **二进制正文。** 研究描述符为 1 B 模式＋2 B 大端原长，位于受认证的帧内。在现有 2,048 B 内层限额下，3 B 描述符给编码流留下 2,045 B。完整原文仍可达 2,048 B；不可压缩且放不下时明确拒绝。为二进制用途定义独立的认证区分方式，精确文本与集句间的交叉解释必须失败。正式编号、绑定域、版本发布策略和旧配置保留期在 ADR 中确认。现有文本接口及固定向量作为回归契约。[现有封装](../../security/src/main/kotlin/dev/zeroinput/security/message/MessageEnvelope.kt)
- **长度恢复。** 单层 AES 原型可用混合进制累积容量跨越的唯一 64 B 档推回长度；检测过的封装长度为 162–2,210 B。该性质尚未验证到其他层序、随机数开销和凭据组合。第一阶段只验已实测组合；扩展前须证明可唯一恢复，或按研究设计先恢复 44 B 公共头、再恢复并认证元数据、最后恢复正文。分段终止的损耗要重新计入 20%。禁止靠多次尝试凭据或模式消歧。
- **完整表面绑定。** 主机原型把配置摘要用于测试 cover。正式方案需评审域分离、密文与规范表面的唯一对应、修改配置或任何可见字符后的失败行为，避免把尚未生成的完整诗文作为加密前的输入。压缩器每条消息单独初始化；不使用跨消息历史，不把攻击者控制的公开段与秘密混压。报告可观察的长度桶及选择泄露，限制错误信息与 KDF 次数。加密与认证沿用已审查的原语。[现行 ADR](../adr/0039-text-steganography.md) · [威胁模型](../threat-model.md)

### P1 原始任务卡

1. 先复跑 P0。阅读[变长码参考](../../tools/themed-verse/word_codec.py)、[主机编解码器](../../tools/themed-verse/binary_prototype.py)、[静态位置实现](../../tools/themed-verse/rime_location_codec.py)与[位置实验收发](../../tools/themed-verse/rime_location_probe.py)。记录现有 v1 公开向量哈希。部分基线输入取自仍在编辑的仓库文档开头；固定其来源提交、截取与换行口径及实际输入字节哈希，再比较前后结果。
2. 在 P1 独立研究配置下，先写“收端只得到配置、公开夹具密钥、成品文件”的测试。用至少一个实际选中位置＋固定字典压缩的样本、一个实际选中自定义变长码的样本、一个含未知字和 CRLF 的样本。发送、接收分进程；收端不得加载原文样本、发送端候选清单或由本次原文生成的反查表。
3. 完成资源构建、模式注册与封装择优。增加固定的选中模式、原长、压缩流、封装长度、成品及恢复摘要向量；公共密钥仅用于已标明的测试。复跑九篇实际文档，分别列出各路流长度、实际选择、封装档、V、恢复和拒绝原因。用固定向量守住已有增益，随机试验逐条核对 20% 和两种硬上限。
4. 同一测试入口覆盖损坏和低容量；提供从仓库根目录运行的命令，回写项目进度。完成 P1 后先交付主机证据和 P2 语料需求。产品协议、Android 入口、扩容与跨设备指纹凭据仍按各自评审处理。

## 6. 验收与停止条件

| 维度 | 必测内容与判定 |
|---|---|
| 字节正确性 | 跨进程逐字节一致；覆盖 1、2,045、2,046、2,048 B，填充档边缘，可压缩／不可压缩，UTF-8 多字节边界。拒绝越界行号、重复或非法码、截断字面量、错误原长、非零补位、尾随流和膨胀解压；失败不创建结果文件、不发布部分正文 |
| 认证与载体 | 改单字（含另一合法候选）、换标点／换行、改末段、调换句序、追加截断、错主题／资源／凭据、篡改头部／元数据／正文／任一标签。旧精确文本向量及不支持的层序负向用例均须通过 |
