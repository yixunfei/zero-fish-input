# 二进制正文与集句主机原型

此工具用于公开测试材料。它把 1–2,048 B 的严格 UTF-8 原文无损压缩为二进制，用随机密钥凭据模式的实际单层 AES 封装加密，再生成分段的 UTF-8 集句。接收方需要同版资源、32 B 夹具密钥和成品全文。封装长度、原文长度、编码类型均无需另行传递。

## 运行

从仓库根目录使用 Python 3.10+、Rust 工具链和锁定诗词表。首次构建需准备 Cargo.lock 中的主机依赖，缓存齐备时可给两条构建命令加 `--offline`。主机实验和解码本身离线运行。

```powershell
cargo build --locked --manifest-path tools/stego-vectors/Cargo.toml
cargo build --locked --release --manifest-path tools/themed-verse/rmw-probe/Cargo.toml --target-dir .tmp-evidence/rmw-target
python -B tools/themed-verse/check_binary_prototype.py
```

下面的例子使用公开的 v0.7.6 说明。每次运行创建一个新的临时目录，输入和输出按原始字节读取和比较。普通文件用法为 `seal key input output` 和 `open key carrier output`。输出必须是新文件。`--require-20` 会在写入前检查实际利用率，普通研究模式同时允许测量低于门槛的样本。

```powershell
$trial = Join-Path ([IO.Path]::GetTempPath()) ([guid]::NewGuid().ToString())
New-Item -ItemType Directory -Path $trial | Out-Null
python -c "import os,sys;from pathlib import Path;Path(sys.argv[1]).write_bytes(os.urandom(32))" "$trial/key.bin"
python -c "import sys;from pathlib import Path;Path(sys.argv[1]).write_bytes(Path('docs/releases/v0.7.6.md').read_text(encoding='utf-8').encode())" "$trial/public.txt"
python -B tools/themed-verse/binary_prototype.py seal "$trial/key.bin" "$trial/public.txt" "$trial/verse.txt" --require-20
python -B tools/themed-verse/binary_prototype.py open "$trial/key.bin" "$trial/verse.txt" "$trial/recovered.txt"
python -c "import sys;from pathlib import Path;a,b=map(Path,sys.argv[1:]);assert a.read_bytes()==b.read_bytes();print('PASS byte-for-byte')" "$trial/public.txt" "$trial/recovered.txt"
```

## 编解码约定

1. 只用截至 v0.7.3 的公开版本说明训练码表。单字、出现至少三次的 2–4 字汉字片段及短 ASCII 词作为候选。按频数和字节收益排序裁剪，固定平局顺序，构建确定性 Huffman 树。v1 得到 1,370 个符号（含转义）。转义后用 4 位表示 1–16 个原始字节的长度，再原样写入字节。动态规划比较所有可用词、字及字面量路径的总位数。高位先写，最后不足一字节补零。原文不做换行或 Unicode 归一化。
2. 每种候选编码均须逐字节解回原文，且编码流加 3 B 描述符不超过现有 2,048 B 帧内正文限额。按实际封装档位选最小值。同档按原始 UTF-8、zlib、自定义码表、固定字典 UTF-8、固定字典 GB18030、RMW 的顺序取第一项。RMW 不能精确恢复的输入会从候选中剔除。原样回退同样受帧限额约束。没有合格候选即拒绝。
3. 描述符含 1 B 编码编号和 2 B 大端原文长度。压缩流直接进入原有主机参考封装的正文位置。沿用 44 B 头、已认证元数据、64 B 填充档、XChaCha20-Poly1305 元数据认证和 AES-256-GCM 正文认证。随机盐、随机数及填充均由操作系统提供。只加密一次，随后的完整回读用于自检。固定公开配置摘要参与原封装的 cover 绑定。Android 现有的严格文本入口不解析此主机描述符。
4. 沿用主题衔接的混合进制码本及唯一版式。相邻两句依次用逗号、句号，最后一句以句号收束，每四句之间用一个 LF。收端先校验整篇版式及两种长度，再由最后一句使候选池大小的累积乘积首次越过的帧档恢复密文字节数，解析所选词面。串改合法词面会改变密文；两层认证均成功后才解释编码编号和解压。解压限制输出和原长，检查尾随数据与补位。资源、布局或码表变化须另设配置。

## 第一版结果

下表为一次真实加密、从成品回读并逐字节比较的结果。盐和填充每次随机，混合进制会使个别成品长度略有变化。利用率分子为原始正文 UTF-8 长度，分母含全部标点与换行。训练文件与这几组输入分开；追加的三篇属于同项目技术文本，不能代表自然聊天。

|---|---:|---:|---|---:|---:|---:|
| 自然措辞设计 | 2,048 | 1,232 | RMW | 1,186 | 12,920 | 15.85% |
| 剪贴板设计 | 2,048 | 1,016 | GB 字典 | 1,058 | 11,515 | 17.79% |
| v0.7.4 | 1,281 | 487 | UTF-8 字典 | 610 | 6,642 | 19.29% |

| v0.7.6 | 1,430 | 532 | GB 字典 | 610 | 6,642 | 21.53% |

九篇实际文档全部恢复、两篇过 20%，一篇合成对照恢复并过线。自定义编码有一次进入最小封装档，没有提高过线样本数。[固定公开向量](binary-vector.json) 包括一次独立保存的自定义流、公开夹具密钥、成品和原文摘要；验收还覆盖跨进程回读、错密钥、标签／正文／元数据修改、资源错配、截断、非规范换行、失真 RMW、过大解压与尾随流。既有主机密码向量仍逐行对应原结果。

此版本只处理主机公开夹具，未进行跨设备实现对照、密码评审或整篇自然度盲评。观测到的容量与原主题集句基线一致。下一步应优先验证整篇可读性与非模板中文的压缩收益，再决定是否值得评审二进制产品入口。[研究门槛](../natural-wording-steganography.md)

## 默认词库位置与原引擎按键重放

在同一批公开正文上增加三组加密前编码对照。锁文件中的 16 张默认词表共扫描 2,214,029 个数据行（含重复读音与词面）。实验只在内存中索引语料实际需要的词，但行号按全库确定，收端从位置流反查同一份完整资源。全程使用隔离的 emulator 临时目录，直接调用项目 x86_64 librime。采用默认无可选语法模型的预编译方案、简体转换、关闭用户词典。模拟的是原生按键转换，未经过 IME 面板的应用层二次排序。

* **词库位置**。ASCII 原样，常用单字和基础词用 2 B，其他可定位行用 3 B。动态规划在词、短语、完整匹配的汉字句段和 UTF-8 字面量间选最短字节流。真实文档和训练样本不参与行号分配。
* **模拟输入**。从读音表得到全拼与首字母，另对连续汉字段尝试完整输入。向 librime 逐键输入最多 64 个字母，取前 32 个候选。记录每个字母的 5 位编码、按键长度和实际候选序号，常见长度的首选可省略序号。多音词取最高权重读音，本次未穷举所有键序或输入历史。
* **混合**。词库位置与键序同时可选。三组都比较原字节流、zlib 和以 v0.7.3 及之前版本说明训练的固定字典 zlib。每组实际还原原始 UTF-8，原长和编码类型沿用合计 3 B 的认证描述符预算。收端独立重建训练字典、解析位置与键序，在新的引擎进程中重放实际用到的 680 个不同键序；没有把候选列表算作双方免费共享的消息数据。

共测试 4,661 个不同键序。例如 `shurufa` 首选为“输入法”，`srf` 第二候选才是“输入法”；`mysjz`、`qqssl` 首选分别为“明月松间照”“清泉石上流”。两句都能回读。9 篇实际文档中，模拟输入的最短流均长于 v1；允许模拟输入与行号混用后，在本次各样本上均未比词库位置方案再省字节。

下表为单次完整验收。前三个长度列取各组最短流，含二次压缩；v1 同封装档可按优先级选更简单、略长的流。真实加密链路只在词库位置使封装降档时替代 v1，使用独立主机测试配置绑定；随机加密后生成实际 UTF-8 成品，收端从成品推回长度、验证两层认证并恢复原文。密文长度相同的重复运行可能因随机数导致少量成品长度差异。

v0.7.5 的 1,108 B 原文用位置与字面量表示后为 676 B，再用普通 zlib 为 609 B，用转换后的固定公开字典压缩为 291 B。可复用的是位置序列与同类文本的重复结构。最终 9 篇实际文档有 6 篇降一个封装档，超过 20% 的从 2 篇增加到 4 篇。另两组对照不计入分母。这个实验只缩短加密输入，成品仍用原集句规则。尚待验证更广体裁的收益、其他版本／平台候选一致性和整篇自然度。建议将静态位置方案作为候选，保留 v1 的回退。
